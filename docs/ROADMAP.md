# Plano técnico e critérios

| Fase  | Entrega verificável                                          |
| ----- | ------------------------------------------------------------ |
| 0     | Arquitetura, benchmark, limites de domínio, dependências     |
| 1     | Tokens, tipografia, shell responsivo, componentes e foco     |
| 2     | Auth, migrations, ownership, RBAC, RLS e auditoria           |
| 3     | Onboarding, movimentos, contas, orçamento e persistência     |
| 4     | Motor determinístico com testes de dinheiro, datas e limites |
| 5–6   | Responses API, extração validada, busca RAG e fontes         |
| 7     | Webhook assinado, vínculo, áudio, idempotência e desfazer    |
| 8     | Metas, jornada, score explicável, cenários e plano semanal   |
| 9     | Empresas, equipe, DRE, fluxo e simulação de contratação      |
| 10–11 | Exportação/exclusão, validação, isolamento e testes E2E      |
| 12–13 | CI/Pages, instruções de ativação e documentação operacional  |

O escopo solicitado é de produto, não apenas uma tela. A matriz de entrega em `docs/STATUS.md` deve distinguir implementação, testes locais e validação externa. Nenhuma integração é considerada homologada apenas por existir código ou compilar.
